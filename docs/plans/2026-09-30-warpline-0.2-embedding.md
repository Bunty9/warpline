# warpline 0.2 Implementation Plan

> **For agentic workers:** execute task-by-task with
> superpowers:subagent-driven-development. Each task ends green
> (`cargo test --workspace` with and without `WARPLINE_TEST_DATABASE_URL`,
> `cargo clippy --workspace --all-targets -- -D warnings`,
> `cargo fmt --all --check`) and gets an Opus review before the next starts.

**Goal:** make `warpline-core` embeddable in someone else's app in ~20 lines,
fix every bug from the 2026-09-30 audit, ship a full end-to-end reference
example, and release 0.2.0 through crates.io trusted publishing.

**Architecture:** a new `warpline_core::Runtime` owns every piece that is
easy to get wrong today (engine, linker, epoch ticker, guarded HTTP client,
component cache, admission control, metering sink). Postgres-specific pieces
move to a feature-gated `warpline_core::pg` module that lives in its own
`warpline` schema. `warpline-host` and `warpline-control` become thin HTTP
layers over `Runtime` + `pg`, and the example uses exactly the same API.

**Tech stack:** Rust 1.96+, wasmtime 49 (Component Model), axum 0.8, tokio,
sqlx 0.8 / Postgres 16, wit-bindgen 0.62 guests on `wasm32-wasip2`.

**Source of requirements:** the 2026-09-30 Opus audit (sections A–D,
summarised per task below).

## Global constraints

- Version 0.2.0 for all three crates; breaking changes are allowed, and are
  listed in `CHANGELOG.md`.
- Commits authored by `Bunty9 <Bunty9@users.noreply.github.com>`, with no
  AI attribution in any commit, PR or release note.
- No new `unsafe` reachable from safe public API.
- The public API returns typed errors (`thiserror`), not `anyhow`.
- Every public struct or enum that may grow is `#[non_exhaustive]` and
  implements `Debug`.
- Keep `cargo deny check` green, and keep `cargo package --workspace`
  buildable.
- Guests stay pinned by `examples/rust-toolchain.toml` (1.98.0).

## Review focus (failure modes no single task's happy path covers)

1. An embedder drops every `Runtime` clone while an invoke is still in
   flight. The ticker must stay alive until the invoke finishes, because
   in-flight invokes hold an `Arc`.
2. The embedder's database already has `tenants`, `functions` or
   `_sqlx_migrations`. `pg::migrate` must not touch or read them.
3. A burst of concurrent invokes whose memory caps together exceed
   `memory_budget_bytes`. The excess must get `Overloaded` (503); the host
   must not run out of memory.
4. A guest returns malformed or oversized output. The host caps it, and the
   example app treats it as untrusted.
5. Postgres disappears mid-run. Invokes of cached keys keep working, meter
   rows are retried and then counted as dropped, and nothing hangs longer
   than the statement timeout.

## Task 1: `pg` module, schema isolation, metering sink

**Files:**
- `crates/core/src/pg/{mod,auth,admin,meter}.rs`, replacing `auth.rs` and

- `crates/core/migrations/0001_warpline.sql`, which squashes 0001 and 0002.
- `crates/core/Cargo.toml`: add a `postgres` feature (on by default) that

**Interfaces produced:**

```rust
// crate root (always available)
pub struct Usage { pub cpu_us: u64, pub wall_us: u64, pub mem_peak_bytes: usize }   // non_exhaustive, Copy
pub trait MeterSink: Send + Sync + 'static {
    fn record(&self, tenant: &str, func: &str, usage: Usage, ok: bool); // must not block
}
pub struct Limits { pub cpu_budget_ms: u64, pub mem_cap_bytes: usize, pub allowed_hosts: Vec<String> } // non_exhaustive
impl Default for Limits                        // 100 ms, 64 MiB, no hosts
impl Limits {
    pub fn new(cpu_budget_ms: u64, mem_cap_bytes: usize) -> Result<Self, ConfigError>;
    pub fn with_allowed_hosts(self, hosts: &[String]) -> Result<Self, ConfigError>; // normalises
}

pub async fn migrate(pool: &PgPool) -> Result<(), MigrateError>;

impl Authenticator {
    pub fn new(pool: PgPool, ttl: Duration) -> Self;
    pub async fn authenticate(&self, tenant: &str, bearer: Option<&str>) -> Result<AuthOutcome, AuthError>;
}
pub enum AuthOutcome { Authorized(Limits), MissingOrUnknownKey, WrongTenant } // non_exhaustive
pub async fn create_tenant(pool: &PgPool, name: &str, limits: Option<&Limits>) -> Result<IssuedKey, AdminError>; // idempotent, issues a new key each call
pub async fn set_limits(pool: &PgPool, name: &str, limits: &Limits) -> Result<(), AdminError>;
pub async fn usage_summary(pool: &PgPool, tenant: &str, since: DateTime) -> Result<UsageSummary, sqlx::Error>;

pub struct PgMeter; impl MeterSink for PgMeter

impl PgMeterHandle { pub async fn shutdown(self, timeout: Duration) }
```

**Requirements:**
- **Schema isolation (A2).** Every object lives in schema `warpline`.
  - `migrate` takes one connection, runs `CREATE SCHEMA IF NOT EXISTS warpline`
    and `SET search_path TO warpline` on it, then runs the embedded migrator
    on that same connection, so `_sqlx_migrations` is created inside
    `warpline`.
  - Every runtime query is schema-qualified (`warpline.tenants`, ...).
  - Nothing migrates implicitly; the binaries call `migrate` explicitly.
  - Drop `pgcrypto`; `gen_random_uuid()` is built in from Postgres 13.
  - The meter table gains a `wall_us` column.
- **Metering reliability (A4).**
  - `PgMeter` inserts in batches of up to 200, retrying each batch with
    bounded exponential backoff (3 attempts).
  - Each query is wrapped in `tokio::time::timeout(5 s)`.
  - Rows dropped because the channel was full or retries ran out are counted
    in `dropped()`.
- **No global auth state (C).** The auth cache moves into
  `Authenticator`; nothing reads environment variables inside the library.
- **Admin logic moves into `pg::admin`** from `warpline-control`: the
  transaction, validation and key issuance.
- **Tests** (Postgres-gated, one unique schema-safe tenant per test):
  - a pre-existing `public.tenants` table plus a `public._sqlx_migrations`
    table are left untouched by `migrate`, and `migrate` is idempotent;
  - authenticate returns authorized / unknown / wrong-tenant correctly;
  - the auth cache TTL is respected, and TTL 0 disables the cache;
  - `create_tenant` is idempotent and issues a new key each call;
  - meter rows land with the expected `cpu_us`, `wall_us` and `ok` values;
  - a meter pointed at a dead pool retries, counts the rows as dropped, and
    does not hang.

## Task 2: `Runtime` facade, API hygiene, core bug fixes

**Files:**
- `crates/core/src/runtime.rs` becomes the facade.
- The current invoke internals move to `crates/core/src/sandbox.rs`
  (`pub(crate)`).
- `cache.rs` and `registry.rs` become `pub(crate)` apart from `digest`.
- `lib.rs` re-exports the public types listed below.

**Interfaces produced** (at the crate root):

```rust
pub use wasmtime;                              // version-matched re-export
#[derive(Clone)] pub struct Runtime(Arc<Inner>);   // Debug
pub struct RuntimeConfig {                     // non_exhaustive, Clone, Debug
    pub modules_dir: PathBuf,
    pub allow_private_egress: bool,            // one flag drives both the client resolver and IP-literal checks
    pub memory_budget_bytes: usize,            // default: 1 GiB; admission weight = limits.mem_cap_bytes
    pub max_in_flight_per_tenant: usize,       // default: 32
    pub max_output_bytes: usize,               // default: 8 MiB
    pub component_cache_entries: usize,        // default: 256
    pub component_cache_bytes: usize,          // default: 512 MiB
    pub compile_concurrency: usize,            // default: max(1, cores/2)
}
impl RuntimeConfig { pub fn new(modules_dir: impl Into<PathBuf>) -> Self }
pub struct RuntimeBuilder;
impl RuntimeBuilder {
    pub fn kv(self, kv: Arc<dyn KvStore>) -> Self;
    pub fn meter(self, sink: Arc<dyn MeterSink>) -> Self;
    pub fn build(self) -> Result<Runtime, Error>;
}
impl Runtime {
    pub fn new(cfg: RuntimeConfig) -> Result<Self, Error>;           // MemKv, no meter
    pub fn builder(cfg: RuntimeConfig) -> RuntimeBuilder;
    pub fn engine(&self) -> &wasmtime::Engine;
    pub async fn stage(&self, wasm: Bytes) -> Result<Staged, PublishError>;   // compile (spawn_blocking + semaphore) + typecheck + persist blobs
    pub async fn activate(&self, tenant: &str, func: &str, staged: &Staged) -> Result<(), PublishError>; // atomic pointer write
    pub async fn publish(&self, tenant: &str, func: &str, wasm: Bytes) -> Result<Staged, PublishError>;   // stage + activate
    pub async fn invoke(&self, tenant: &str, func: &str, input: Vec<u8>, limits: &Limits) -> Result<Invocation, InvokeError>;
    pub async fn gc(&self, grace: Duration) -> Result<usize, Error>;
}
pub struct Staged { pub digest: String }                 // non_exhaustive
pub struct Invocation { pub output: Vec<u8>, pub usage: Usage } // non_exhaustive
pub enum InvokeError {                                   // non_exhaustive, thiserror
    InvalidName, NotFound, Overloaded, TenantBusy,
    CpuBudgetExceeded { usage: Usage, budget_ms: u64 },
    MemoryCapExceeded { usage: Usage, cap_bytes: usize },
    WallClockTimeout { usage: Usage },
    OutputTooLarge { usage: Usage, limit: usize },
    GuestTrap { usage: Usage, #[source] source: wasmtime::Error },
    Load(#[source] Error),
}
impl InvokeError { pub fn usage(&self) -> Option<Usage>; pub fn http_status(&self) -> u16; }
pub enum PublishError { InvalidName, Compile(..), ImportMismatch(..), Io(..) } // non_exhaustive
pub enum Error { .. }                                    // non_exhaustive, the crate's general error
```

**Requirements:**
- **Ticker lifetime.** The `Runtime` owns its `EpochTicker`, which stops only
  when the last `Arc<Inner>` is dropped. Each in-flight invoke holds a clone.
- **Admission control (A1).**
  - A memory-weighted semaphore: `try_acquire_many` of `mem_cap_bytes`
    rounded up to MiB, returning `Overloaded` when it can't.
  - A per-tenant in-flight counter, returning `TenantBusy`.
  - Output larger than `max_output_bytes` returns `OutputTooLarge`.
- **Metered CPU (A5).** `cpu_us` counts epoch ticks × 1000; `wall_us` is
  reported separately.
- **Budget floor (A8).** The deadline callback allows one extra tick, so the
  effective budget is (budget, budget + 1] ms. An echo with a 1 ms budget
  must succeed 100 times in a row.
- **Registry fixes.**
  - GC aborts on pointer read errors other than `NotFound` (A3).
  - A failure to persist the recompiled `.cwasm` is logged; the invoke still
    succeeds (A11).
  - Re-uploading bytes that already exist bumps the source file's mtime
    (A12).
  - The linker lives behind an `Arc` (A6).
  - The `ComponentCache` belongs to the runtime, so its engine and linker
    always match.
- **Hygiene (C).**
  - Functions that deserialize `.cwasm` are no longer safe public API.
  - `HostCtx` and `TenantLimiter` fields are private.
  - `invoke` internals use `pre.engine()`.
  - `EpochTicker` is `pub(crate)`.
  - `KvStore::get` returns `Result<Option<Vec<u8>>, KvError>`, and `KvError`
    gains `Backend`.
  - Add `Debug` to every public type.
  - Drop unused dependencies (core: serde, serde_json; the sqlx `chrono`
    feature unless used).
- **Tests.** Port all 16 runtime tests to `Runtime`, and add:
  - a burst of concurrent invokes returns `Overloaded`;
  - the per-tenant in-flight cap returns `TenantBusy`;
  - oversized output returns `OutputTooLarge`;
  - a 1 ms budget echoed 100× all succeed;
  - dropping the `Runtime` while an invoke is in flight still traps the loop
    (the ticker stays alive);
  - `cpu_us` stays under 2× the budget even while another tenant's loop runs
    concurrently;
  - GC with an unreadable pointer errors and deletes nothing;
  - the recompile path works on a read-only cwasm dir.
- **Benches** and the doc examples on `Runtime` (a runnable doctest
  showing the ~15-line embed) are updated.

  metering.
- Status mapping comes from `InvokeError::http_status()`: 503 Overloaded,
  429 TenantBusy, 408 CPU/wall, 507 memory, 502 OutputTooLarge, 500 trap,
  404, 400.
- Treat empty environment variables as unset (A13).
- Control shuts down gracefully (A7), and `shutdown_signal` moves into a
  shared place (core or host).
- In embedded mode the control task's `JoinHandle` is awaited with a
  timeout (A10).
- Control uploads: `stage` → quota transaction under the tenant advisory
  lock → `activate` **before** commit, restoring the previous pointer if the
  commit fails (A9).
- `warpline-host` depends on `warpline-control` only behind an
  `embed-control` feature (on by default). Remove unused dependencies (host:
  tower-http, sqlx, serde, serde_json, thiserror, bytes; control:
  tower-http, thiserror, bytes; `tower` becomes a dev-dependency).
- `metrics_handle()` must not panic when a recorder is already installed.
- **Docs (D).** Fix every README / PROGRESS / doc-comment error in the audit.

## Task 4: reference example `examples/storefront`

A standalone project, outside the workspace, depending on
`warpline-core = "0.2"` with a `[patch.crates-io]` path override. The
override is marked as the only line a copier deletes.

**Scenario:** a storefront where each merchant (tenant) uploads a checkout
hook. At checkout the app invokes the merchant's hook with the order, then
applies the returned decision.

- **`app/`** is an axum binary embedding `Runtime` + `pg`.
  - Routes:
    - `POST /admin/merchants` (admin token): `pg::create_tenant` with
      limits, returns the API key.
    - `PUT /merchant/hook` (merchant key): `publish` the wasm body.
    - `POST /shops/{merchant}/checkout` (public): build the order, invoke
      the hook, validate the decision, respond.
    - `GET /merchant/usage` (merchant key): `pg::usage_summary`.
    - `GET /healthz`.
  - Treats hook output as untrusted: size, JSON schema, and
    `discount ≤ subtotal`.
  - An explicit fail-open/fail-closed policy per error class, documented.
  - Graceful shutdown drains the meter.
  - Has a second binary, `fraud-mock`, a tiny HTTP service the hook calls
    through `http-out`.
- **`hook/`** is a Rust `wit-bindgen` guest (`wasm32-wasip2`) using all three
  imports:
  - **kv:** a per-customer order counter gives a 10% loyalty discount from
    the third order.
  - **log:** logs each decision.
  - **http-out:** asks `fraud-mock` for a risk score and rejects above 80.
  - Uses serde_json for input and output.
- **`docker-compose.yml`:** postgres + fraud-mock + app.
- **`demo.sh`** drives the full flow with assertions (curl + jq-free checks):
  create merchant → upload hook → three checkouts showing the discount
  kicking in → a risky customer rejected → a disallowed host shown failing
  → usage summary.
- **`README.md`:** a walkthrough explaining each integration point, with
  links into the code.
- **`app/tests/e2e.rs`:** the same flow in Rust against a real Postgres
  (gated on `WARPLINE_TEST_DATABASE_URL`), using a prebuilt hook fixture
  that `build.sh` refreshes.
